# 居眠り運転検知システム

Webカメラの映像から運転者の目・口の状態をリアルタイムに解析し、居眠りの兆候を検知して音声で警告するシステムです。

## 開発の背景

居眠り運転による交通事故は、発見が遅れやすく重大事故につながりやすいという特徴があります。運転者自身も眠気の進行に気づきにくいことが多く、眠気や疲労によって注意力が低下すると、重大な交通事故につながる可能性があります。
また、運転者自身が覚醒度の低下を早い段階で認識することは難しい場合があります。

そこで、技術の力でこの「気づきにくさ」を補い、事故を未然に防ぐ仕組みをつくりたいと考え、顔のランドマーク検出を用いて運転者の覚醒状態をリアルタイムに判定するシステムを開発しました。

## 技術構成

| 技術 | 用途 |
|---|---|
| Python | 実装言語 |
| OpenCV | カメラ映像の取得・描画 |
| MediaPipe (Face Landmarker) | 顔ランドマークの検出 |
| pyttsx3 | 音声警告の読み上げ |
| winsound | 警告音（ビープ音）の再生 |

## 判定ロジック

### EAR（Eye Aspect Ratio）
目の縦方向・横方向のランドマーク間距離から算出する、目の開閉度を表す指標。値が小さいほど目を閉じている状態を示す。

EAR = (縦方向距離1 + 縦方向距離2) / (2 × 横方向距離)

### MAR（Mouth Aspect Ratio）
口の縦横比から、あくびなど口の開き具合を検出する指標。

### PERCLOS（PERcentage of eyelid CLOSure）
直近30秒間のフレームのうち、目を閉じていたフレームの割合。長時間の疲労傾向を捉えるための指標。

> **開発中に見つけた課題**：当初はプログラム開始からの全フレームでPERCLOSを累積計算していたため、起動直後に数回まばたきしただけで割合が跳ね上がり、その後もなかなか下がらず誤検知するという不具合があった。直近30秒間のみを見るスライディングウィンドウ方式に変更し解消した。

### 状態判定
上記3指標を組み合わせ、危険度の高い順に以下の4段階で判定する。

1. **DROWSY**（危険）：長時間の閉眼、またはPERCLOSが40%超
2. **TIRED / YAWNING**（疲労・あくび）：あくび検出、またはPERCLOSが20%超
3. **CLOSED**（一時的な閉眼）：瞬き等の短時間の閉眼
4. **OPEN**（通常）：覚醒状態

DROWSYまたはTIRED / YAWNING状態が続く場合、5秒間隔で音声警告を発する。

## セットアップ

### 必要環境
- Python 3.9以上
- Webカメラ

### インストール

```bash
pip install opencv-python mediapipe pyttsx3
```

※ `winsound`はWindows標準ライブラリのため別途インストール不要（Windows専用）。

### モデルファイルの準備

以下2つのモデルファイルをリポジトリ直下に配置してください。

- `face_landmarker.task`（[MediaPipe公式](https://ai.google.dev/edge/mediapipe/solutions/vision/face_landmarker)より取得）
- `blaze_face_short_range.tflite`（[MediaPipe公式](https://ai.google.dev/edge/mediapipe/solutions/vision/face_detector)より取得）

### 実行

```bash
python drowsiness_detection.py
```

`q`キーで終了します。

## ファイル構成

開発は以下の順で段階的に進めた。

| ファイル | 内容 |
|---|---|
| `main.py` | Webカメラ映像の取得・表示確認（動作検証用） |
| `face_detection.py` | MediaPipe Face Detectorによる顔検出 |
| `eye_landmark.py` | 目周辺のランドマーク検出・描画 |
| `eye_ear.py` | EARによる開閉眼判定 |
| `drowsiness_detection.py` | EAR・MAR・PERCLOSを統合した完成版。音声警告機能付き |

## 今後の課題

- あくびを1回検出しただけで疲労状態と判定する現在のロジックを、一定時間内のあくび回数も考慮する方式へ改善
- PERCLOSの閾値（現在20%/40%）は仮の値のため、実際の被験者データをもとに適切な値へ再調整
- 現在はWindows専用（`winsound`依存）のため、クロスプラットフォーム対応を検討
- 実際の車載環境（夜間・逆光・眼鏡装着時など）での精度検証
- 被験者を増やし、EAR・MARなどの閾値の個人差を検証検証
